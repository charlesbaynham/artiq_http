# Agent Interface

Enable LLM-based agents (e.g. GitHub Copilot, Claude, custom tool-calling agents) to interact with ARTIQ through artiq_http using structured tool calls.

## Problem

Agents need to:
- Discover available experiments and their argument schemas
- Submit experiments with correct arguments
- Monitor experiment status and wait for completion
- Read back result datasets after an experiment finishes

The existing REST API already covers the raw operations, but lacks conveniences that make agent workflows reliable without excessive polling or complex client logic.

## Goals

- Generate a **typed Python SDK** using [Fern](https://buildwithfern.com/) from the FastAPI OpenAPI schema
- Package the SDK as an **agent skill** so that any agent in this repo automatically knows how to use it
- Add a small number of **REST API improvements** that make common agent patterns easier
- Keep the existing API unchanged (backward-compatible additions only)

## REST API additions

### 1. Per-RID status endpoint

```
GET /api/schedule/{rid}
```

Returns the schedule entry for a single RID, or 404 if not found. Saves agents from fetching the full schedule to check one experiment.

Response (if running):
```json
{"rid": 42, "status": "running", "pipeline": "main", "priority": 0, "expid": {...}}
```

Response (if not found / completed):
```json
404 Not Found
{"detail": "RID 42 not found in schedule"}
```

### 2. Experiment argument defaults

```
GET /api/explist/{file}/{class_name}/defaults
```

Returns a pre-filled `arguments` dict with default values extracted from `arginfo`. Lets an agent construct a valid `ExpID` without having to parse arginfo itself.

Response:
```json
{
  "file": "repo/my_exp.py",
  "class_name": "MyExperiment",
  "arguments": {
    "num_shots": 100,
    "frequency": 100.0e6
  }
}
```

### 3. Experiment search / filter

```
GET /api/explist/search?q=rabi
```

Returns a filtered subset of `/api/explist` matching the query against experiment name, file, or class name (case-insensitive substring). Reduces the payload an agent needs to process when looking for a specific experiment.

### 4. Submit and poll (long-poll)

```
POST /api/schedule/submit-and-wait?timeout=60
```

Body: same as `POST /api/schedule` (`ExpID` + pipeline/priority etc.)

Submits the experiment, then holds the HTTP connection open until the RID leaves the schedule (i.e. completes or is cancelled), or `timeout` seconds elapse (default 60, max 300).

Response on completion:
```json
{"rid": 42, "status": "done", "timed_out": false}
```

Response on timeout:
```json
{"rid": 42, "status": "running", "timed_out": true}
```

This is the most important addition: it gives agents a single call they can await rather than polling.

### 5. SSE dataset stream (already planned)

See [sse-updates.md](sse-updates.md). Agents that watch for specific dataset keys can subscribe to the stream rather than polling `/api/datasets`.

## Python SDK (Fern-generated)

The SDK is generated by [Fern](https://buildwithfern.com/) from the FastAPI OpenAPI schema (`/openapi.json`). Fern produces a fully-typed, idiomatic Python package with async support, Pydantic models, and built-in retry/error handling.

### Setup

```
fern/
  fern.config.json       # org + Fern version
  generators.yml         # Python SDK output config
  openapi/
    openapi.json         # exported from FastAPI at build time
```

`fern.config.json`:
```json
{"organization": "artiq-http", "version": "0.x.x"}
```

`generators.yml`:
```yaml
groups:
  python-sdk:
    generators:
      - name: fernapi/fern-python-sdk
        version: 4.x.x
        output:
          location: local-file-system
          path: ../sdk
        config:
          package_name: artiq_http_client
          client_class_name: ArtiqClient
```

The OpenAPI spec is exported once at build time (or on demand) via:
```bash
uv run python -c "
import json
from artiq_http.api import app
print(json.dumps(app.openapi()))
" > fern/openapi/openapi.json
```

Then the SDK is regenerated with:
```bash
fern generate --group python-sdk
```

The generated package lives in `sdk/` and is installable as a local dependency:
```toml
# pyproject.toml
artiq-http-client = {path = "sdk", develop = true}
```

### Usage (agent code)

```python
from artiq_http_client import ArtiqClient
from artiq_http_client.environment import ArtiqHttpClientEnvironment

client = ArtiqClient(base_url="http://localhost:8000")

# Discovery
experiments = client.explist.list()
match = next(e for e in experiments.experiments if "rabi" in e.name.lower())
defaults = client.explist.get_defaults(file=match.file, class_name=match.class_name)

# Submit and wait
result = client.schedule.submit_and_wait(
    expid={"file": match.file, "class_name": match.class_name, "arguments": defaults.arguments},
    timeout=120,
)

# Read results
datasets = client.datasets.get_values(names="rabi.freq_axis,rabi.population")
```

All errors surface as typed `ApiError` exceptions with `.status_code` and `.body`.

### Re-generating after API changes

Whenever a new endpoint or model is added:
1. Re-export the OpenAPI spec (`uv run python -c ... > fern/openapi/openapi.json`)
2. Run `fern generate --group python-sdk`
3. Commit both the updated spec and the regenerated `sdk/` directory

## Copilot skill

Add `.agent/skills/artiq-sdk/SKILL.md` that:
- Describes when to use the SDK (any task involving running ARTIQ experiments, reading datasets, or checking status)
- Shows the import pattern and a worked example covering the common end-to-end flow: search → get defaults → submit_and_wait → get_datasets
- Documents the generated client's resource layout (`client.explist`, `client.schedule`, `client.datasets`, `client.health`)
- Covers `ApiError` handling

Agents in this repo will load this skill automatically when the task involves ARTIQ experiment control.

---

## Out of scope (for now)

- Agent authentication / access control (assumes trusted deployment)
- Streaming experiment log output
- Writing datasets or device_db from the agent side
- Git repository management
